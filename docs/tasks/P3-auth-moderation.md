# P3 會員登入、修正建議與審核後台

**目標：** 網站可以公開上線。訪客照常瀏覽；登入的家長可以提交修正建議（照片先不開放，見 decisions D17）；審核員在後台核准後資料才會更新。

**前置條件：** P1 完成。（P2 補資料可以和 P3 平行進行。）
**資料表：** `supabase/migrations/0002_auth_roles.sql` 已經寫好初版，實作時發現問題可以修改，但要在 PR 說明原因。

## 原則

- **看資料不用登入，寫入才要登入。** 首頁、場地頁、篩選、查路線都不能要求登入。
- **權限在資料庫層把關（RLS 與 `review_suggestion()`），前端隱藏按鈕只是體驗，不是安全機制。**
- 所有修改都留下紀錄：誰提的、誰審的、改之前是什麼。

## 範圍

### 1. 登入（Supabase Auth）

| 方式 | 本階段 | 備註 |
|---|---|---|
| Google | 做 | Supabase 內建 |
| LINE | 做 | **先調查再實作**：確認 Supabase 目前是否支援自訂 OAuth／OIDC provider。若不支援，提出替代方案（例如用 Edge Function 處理 LINE Login 流程再建立 session）並比較風險，寫進 `docs/decisions.md` 經我確認後才實作。**調查結果（2026-10-11）：** 自訂 OIDC 不能用（LINE 網頁登入的 ID token 是 HS256）；P3(b) 先不做，之後實驗 OAuth2 手動模式，見 D10 |
| Email 登入連結 | 做 | 免密碼 |
| Facebook、Apple | 不做 | 見 decisions D10 |

- 登入入口：頁首的「登入」按鈕，以及按「回報修正」「上傳照片」時跳出的登入視窗。登入後回到原本的頁面和操作。
- 第一次登入時建立 `profiles`（trigger 已寫好），預設暱稱是「家長」＋隨機 4 位數（例如「家長 4821」），不用社群帳號名稱，避免公開真名（decisions D16）；可以修改。
- 頁面上只顯示暱稱，不顯示 email 或社群帳號頭像以外的資訊。

### 2. 提交修正建議（取代 P1 的「即將開放」）

在場地頁提供以下幾種回報，全部寫入 `edit_suggestions`，`status = 'pending'`：

| 類型 `kind` | 介面 | `payload` |
|---|---|---|
| `attribute` | 選設施項目 → 有／沒有 → 補充說明 | `{"key","value","note"}` |
| `parking` | 類型、免費／付費、格數、費用說明 | `{"type","fee","spaces","fee_note","note"}` |
| `field` | 開放時間、地面材質等基本欄位 | `{"field","value"}` |
| `closure` | 回報封閉或維修中，可填預計恢復日期 | `{"reason","until"}` |
| `new_place` | 在地圖上標點＋名稱＋地址（從首頁進入） | `{"name","lat","lng","address","city"}` |

- 送出前用 Cloudflare Turnstile 驗證；超過每日上限（資料庫 trigger：24 小時 30 筆）時顯示清楚的訊息。
- 送出後顯示「已收到你的修正建議，審核通過後會更新」。
- 同一個場地、同一個屬性，如果自己已經有一筆待審建議，提示「你已經回報過，正在審核中」，不要重複建立。

### 3. 「我的貢獻」頁 `/me`

- 列出自己提交的建議和照片，以及狀態：審核中、已採納、未採納（附原因）。
- 可以修改暱稱。
- **刪除帳號**：刪除後，個人資料與照片一併刪除；已採納的資料保留，但不再顯示提交者（`user_id` 設為 NULL）。

### 4. 照片上傳（延後，decisions D17）

> 2026-10-11 決定先不開放照片上傳。`photos` 資料表與權限已在 (a) 建好；以下內容留到開放照片時再做。


- Storage 建兩個 bucket：`photos-pending`（私有）、`photos-public`（公開），寫 migration 設定 storage policy。
- 流程：會員上傳到 `photos-pending` → Edge Function **移除 EXIF（含 GPS）**、縮到長邊 1600px、轉成 WebP → `exif_stripped = true` → 進入審核。核准後搬到 `photos-public`，退回則刪除檔案。
- 限制：單檔 10 MB 以內、jpg／png／heic／webp。
- 上傳畫面提醒：「請避免拍到可辨識的孩童臉孔」。
- 場地頁只顯示 `status = 'approved'` 的照片。

### 5. 審核後台 `/admin`

只有 `moderator`（負責縣市）和 `admin` 進得去；其他人導回首頁。

- **待審清單**：可依縣市、場地、類型篩選，預設最舊的排前面，顯示待審總數。
- **對照畫面**：左邊是目前的值（含來源、確認日期），右邊是建議的值（提交者暱稱、此人被採納過幾次、說明）。
- **衝突提示**：同一個場地同一個屬性有多筆待審建議且內容不同時，放在一起顯示。
- **核准／退回**：呼叫 `review_suggestion(id, accept, reason, note)`；退回原因從清單選：重複、無法查證、不當內容、資訊過時、其他。
- **批次操作**：勾選多筆一次核准或退回。
- `field`、`closure`、`new_place` 三種不會自動套用：審核員在後台編輯場地資料後，再按核准。
- **照片審核**：縮圖列表，核准或退回。
- **修改紀錄**：場地頁的後台檢視可以看到 `place_attribute_history`，並可「還原到這個版本」（還原也會留下一筆紀錄）。

### 6. 管理員功能（`admin` 限定）

- 使用者列表：搜尋、調整角色、指派審核員負責的縣市、停權（填原因）與解除停權。
- 被停權的帳號：`app_role()` 回傳 NULL，所有寫入自動失敗；介面顯示「帳號已停權」。

### 7. 法律頁面

- `/privacy` 隱私權政策、`/terms` 服務條款：先放草稿，標註「待法律審閱」，內容要涵蓋：蒐集哪些資料、用途、保存期限、如何刪除帳號，以及使用者貢獻內容的授權（見 decisions D11）。
- 第一次提交建議或照片前，要勾選同意服務條款，並記錄同意時間。（已完成：P3(c)，貢獻的資料採 ODbL，decisions D11）

## 不在範圍

Facebook／Apple 登入、資深貢獻者自動通過、資料完整度儀表板、站內或 email 通知（`/me` 頁先滿足查看狀態的需求）、收藏功能。

## 完成標準

**權限測試**（直接對資料庫跑，用不同身分的 JWT；這組最重要，全部要寫成自動測試）：

- [x] 匿名使用者：可以讀場地資料；不能新增建議、不能上傳照片、不能讀任何人的建議。
- [x] 會員：可以新增自己的建議；不能把 `status` 設成 `accepted`；不能讀別人的建議；不能修改自己的 `role`；不能呼叫 `review_suggestion()`。
- [x] 第 31 筆建議會被拒絕。
- [x] 新竹市審核員：可以審核新竹市的建議；**不能**審核其他縣市的建議；不能審核自己提交的建議。
- [x] 核准一筆 `attribute` 建議後：`place_attributes` 的值和來源（`user`）都更新、`places.attrs` 同步、`place_attribute_history` 多一筆、提交者的 `accepted_count` 加 1。
- [x] 被停權的會員所有寫入都失敗。
- [ ] 待審照片的檔案用公開網址打不開；核准後才打得開；下載下來的檔案沒有 EXIF。（**延後**：照片先不開放，decisions D17；照片「紀錄」的權限已在 (a) 測試）

**端對端測試：**
